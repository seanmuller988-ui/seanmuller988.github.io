Case study · Trading rule · 2026 · Completed

An entry filter designed around a set of losing trades did no better than random filters on earlier data

A filter proposed after a post-mortem on a set of losing trades looked like a clear improvement. Scored on earlier trades with information known before entry, it blocked the better ones.

Look ahead Placebo controls Entry filters Overfitting

The question

My systematic equity research centers on one strategy that trades relative-value effects among U.S. single stocks. I asked for a post-mortem on a set of losing trades from an earlier version of that strategy. The post-mortem proposed entry filters, rules that skip a trade the strategy would otherwise take. The question was whether the best-looking one should be adopted. That filter is not described here.

Initial approach

I then asked what each proposed filter would have done to those same trades. A retrospective scored four candidates, and one stood out: it appeared to improve the result substantially while blocking only a few trades. The retrospective called its own finding a hypothesis, because the filters had been designed after looking at these trades and then scored on them. It decided whether a trade would have been blocked using the daily bar of the entry day.

What broke

Nothing visibly broke. The retrospective was flattering, and a rule designed in response to a set of losses had been checked only against those losses. I asked that it be shown to hold on data that had played no part in its design. It did not.

Investigation

The test used several thousand simulated trades that pre-dated the design sample (a historical backtest of an earlier internal configuration, not a result reported on this site). The rule’s parameters were left as designed. It was built two ways, the hand-built version from the design and a mechanical version using only data from before each entry, and scored under two timing conventions: daily data through the day before entry, and the entry day’s own daily bar, as in the retrospective.

The benchmark was a random filter: block the same number of trades at random, 1,000 times, and count how often the real filter’s kept trades average at least as well.

With information from before entry, the trades the mechanical version blocked averaged about twice the return of the trades it kept. With the entry day’s bar, the sign flipped in both versions.

The analysis named three causes. The entry day’s daily bar closes after the entry, so it includes what happened after the trade was opened, which is tied to the trade’s own outcome. One episode had supplied nearly all of the retrospective’s gain, while in the earlier sample the rule fired on about a quarter of trades, and those routine firings set the average. And the rule had been scored on the trades it was designed on.

What changed

The filter was not adopted. A narrower variant, examined only after the full rule failed, was left as an unconfirmed lead, to be read on later data before it counts.

A standing rule was recorded the same day: score any entry-time rule on information strictly available at entry, run both timing conventions, and treat an effect that appears only with the entry day’s bar as contamination.

Validation

Across twelve nearby parameter settings, the effect stayed within about six basis points of zero. A second placebo, which kept the rule’s mechanics and scrambled its inputs, put the real rule inside the placebo distribution. The narrower variant matched or beat 996 of 1,000 random filters, yet a bootstrap that resampled whole entry days gave a 95% interval for the difference between blocked and kept trades that included zero.

The limits: random filters treat trades as independent, and the report gives a day-level interval only for the narrower variant, not for the main rejection. The counts in the table are therefore too confident in both directions. They support the decision, which needed only that the filter was not better than random; they do not establish that it was reliably worse. The test plan is written as fixed before results but entered version control with them. The earlier sample held no episode like the one that motivated the filter, so the test is silent on such episodes. It also compared average returns only, so it cannot say whether the rule would be worth a lower average as protection against a rare large loss.

Result

The filter as designed was rejected. The finding is narrow: with information available before entry, the rule’s routine firings removed better-than-average trades. The main losing trades that motivated it would still have been blocked under the stricter timing. The rule built around them did not generalize.

What I learned

A rule designed in response to a set of losses is the rule most in need of a test on data that played no part in its design. The trades that motivate it also flatter it.

Scoring an entry rule with the entry day’s own daily bar lets the outcome leak into the decision. The error works in the rule’s favor, so nothing prompts a second look. Other data does not remove it: scored the retrospective’s way, the filter matched or beat every random filter on the earlier sample.

A random filter of the same size is the right first baseline: it separates which trades a rule blocks from how many. When trades entered on the same day move together, its count overstates the evidence, so it needs a day-level interval beside it.

What changed in the research process afterward

The standing rule is the change. It appears in later work. A later audit of a separate idea listed “no same-day-bar usage” among its checks. That check is narrow: the same audit missed a different look-ahead. Later a design note on new model inputs named same-bar contamination as a risk and cited this study. In early October a study of signal ranking took its daily inputs from the day before each signal only.

The two-convention comparison is part of that standing rule for any later entry rule.
